# INC-005 分类自增 ID 漂移，商品显示"未分类"

| 项 | 内容 |
| --- | --- |
| 编号 | INC-005 |
| 日期 | 2026-10 中旬 |
| 等级 | P3（数据展示异常） |
| 影响面 | 部分商品分类名称为空 |
| 状态 | 已修复 |

## 现象

商品列表和详情页中，部分商品分类位置显示为空白或"未分类"。
商品本身能正常打开、能下单，只是分类字段丢了。

## 排查过程

1. 查商品记录：`SELECT id, category_id FROM product WHERE id = ?` → `category_id` 有值，不是 NULL。
2. 关联查询该分类：`SELECT * FROM category WHERE id = <上面那个 category_id>` → **查不到**。
3. 用 `LEFT JOIN` 统计影响范围：

```sql
SELECT p.id, p.name, p.category_id, c.name
FROM product p LEFT JOIN category c ON p.category_id = c.id
WHERE c.id IS NULL;
```

结果有若干条，全部指向已不存在的分类 ID。

4. 回顾操作历史：中间做过分类数据的清理与重建。

## 根因

两类原因叠加：

1. **删除分类后重建**：清空 `category` 表时自增计数器未重置，
   重建的分类从旧的最大值往后继续分配 ID，与历史商品上留存的旧 `category_id` 对不上；
2. **删除前未校验引用**：删除分类时没有检查是否还有商品在引用它，
   留下了一批指向"空地址"的商品记录。

由于本项目按教学场景没有建立数据库外键约束，这类脏数据不会被数据库拦住，只会安静地留在表里。

## 修复

分三层处理：

1. **修数据**：把孤儿商品的 `category_id` 重新指到有效分类，或置为待分类；
2. **修结构**：`schema.sql` 中分类表加 `AUTO_INCREMENT=1`，重建时从 1 开始，避免 ID 漂移；
3. **修入口**：商品发布与编辑接口增加校验——`category_id` 必须在 `category` 表中存在，否则拒绝写入。

## 验证

- 重新执行关联查询，`c.id IS NULL` 结果为空；
- 尝试用不存在的分类 ID 发布商品，接口返回明确错误而不是成功。

## 预防

- **删除操作前先查引用**，这是数据维护的基本顺序；
- 没有外键时，应用层校验就是最后一道防线，不能省；
- 任何"清空再重建"的操作，都要考虑自增序列与历史引用的关系。

## 经验

> 脏数据的可怕之处在于它不报错。
> 系统照常运行，只是某个字段悄悄变成空——直到有人问"这里怎么是空的"。
